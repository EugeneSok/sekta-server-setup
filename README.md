# sekta-server-setup

Інтерактивний скрипт налаштування сервера **Sekta** (Proxmox VE, останні версії).

Меню (порядок = рекомендована послідовність для нового сервера):
1. **Post-install** — вимкнути enterprise repo, ввімкнути `no-subscription`, прибрати "No valid subscription" nag, `apt dist-upgrade`.
2. **GPU passthrough** — детект GPU на хості, пріоритет Intel iGPU, IOMMU + vfio-pci + blacklist драйвера, звільнення framebuffer хоста для Intel. Автовизначення bootloader (GRUB / systemd-boot).
3. **Перевірка IOMMU-груп** — чи GPU у чистій групі (без чужих пристроїв) для безпечного passthrough.
4. **USB storage (exFAT)** — детект флешки, відмова від системного диску (розпізнає корінь на partition / LVM / ZFS), форматування в exFAT якщо інший FS, монтування по UUID з `nofail`, додавання Proxmox directory storage (`content=backup`).
5. **Debian VM** — знайти й завантажити актуальний netinst ISO, створити VM (q35/UEFI, cpu host, 4 ядра, 8 GB ОЗУ, 10 GB диск, virtio, без autostart).
6. **Кнопка живлення → reboot VM** — хост ігнорує power-key, acpid ловить подію → `qm reboot <VMID>`.
7. **Kiosk-дисплей** — Plymouth boot-splash з логотипом SEKTA + Chromium у режимі kiosk (systemd `--user` unit) на **окремій машині-дисплеї** (Debian / Raspberry Pi OS). Можна задати **до 3 сайтів**: один сайт — заблокований повноекранний `--kiosk`; кілька — вкладки у розгорнутому вікні з видимою панеллю вкладок і перемиканням (Ctrl+Tab). **2–3 екрани:** на кожному екрані свій Chromium на весь екран зі своїм сайтом; де стоїть екран, задається годиною на циферблаті відносно головного (3 — праворуч, 9 — ліворуч, 12 — вище, 6 — нижче, проміжні — по діагоналі; дві однакові години — в ряд). На X11, зокрема GNOME, — один Chromium і один профіль на всі екрани: **вхід на сайти один раз** (вікна розставляє `wmctrl`; GNOME для кількох екранів переводиться з Wayland на X11 — `WaylandEnable=false` у GDM, при поверненні до одного екрана Wayland вертається). На labwc / wayfire (Wayland без X11) у екранів 2–3 окремі профілі — вхід на кожному екрані. З кількома екранами відкриті сторінки кожного екрана **запамʼятовуються** (масштаб — окремо для кожного екрана, системний `xrandr --scale`, бо Ctrl+/− у Chromium спільний для сайту в усіх вікнах) — після перезавантаження відкривається те, що було (один екран, як і раніше, щоразу відкриває свої сайти) (скинути: `~/.local/bin/sekta-kiosk-screens --reset`). Ставиться утиліта **«Sekta kiosk — екрани»** (меню програм або **Ctrl+Alt+K** у GNOME, і поверх kiosk; на labwc — з терміналу `sekta-kiosk`): додати/прибрати екран, змінити вихід, розташування й сайт, **заставку екрана** (вбудоване лого SEKTA або своя картинка на чорному тлі після 1–12 годин без миші й клавіатури, розмір картинки 10–100 % екрана, кнопка «Показати» — як виглядатиме), визначити екрани (назва виходу на кожному моніторі), скинути сторінки, перезапустити/зупинити kiosk; масштаб вибраного екрана — кнопками −/+ і «100 %» просто в головному вікні; **«Оновити з файлу (.deb)»** — новий пакет з флешки без втрати екранів і сайтів (пароль адміністратора питає саме вікно утиліти); **«Зібрати діагностику»** — звіт на весь екран, щоб сфотографувати (також файлом у домашній теці й на флешці). Вікно утиліти — GTK 4; без нього — прості вікна zenity. Для Debian без інтернету — **пакет `sekta-kiosk_<версія>+<реліз>_<архітектура>.deb`** з усіма пакетами всередині (`kiosk/build-deb.sh`; `sudo apt install ./….deb`, далі «Sekta kiosk» у меню: перший запуск встановлює kiosk, наступні — керують, новіший пакет пропонує оновлення). Та сама утиліта з флешки — **офлайн-інсталятор** пункту 7 у вікнах (`bash sekta-kiosk.sh` з теки `kiosk/` на флешці; на флешці можуть бути набори пакетів для кількох релізів/архітектур — `debs/<реліз>-<архітектура>/`, береться свій). Додатково: українська розкладка клавіатури (`us,ua`, Alt+Shift), вимкнення засинання екрану/машини, автовхід у систему без жодного вікна пароля (екран блокування GNOME вимкнено; зі сховища ключів «login» знімається пароль — інсталятор один раз питає пароль користувача, Enter — пропустити), вимкнення інших автозапусків браузера цього користувача (два браузери на одному профілі ламали kiosk), закриття огляду «Діяльності» GNOME після входу (інакше вікна чекали кліку). Запамʼятовані сторінки кожного екрана відкриваються як звичайні вікна kiosk (адреса — з останньої сесії Chromium); kiosk закривається коректно, тож сесія зберігається й після перезавантаження. Інсталятор — у теці [`kiosk/`](kiosk/) цього ж репо; запускається від звичайного користувача.
8. **Sekta APP (Debian)** — те саме, що Kiosk-дисплей (boot-splash, автовхід, UA-клавіатура, без засинання), але на екрані замість браузера — **застосунок Sekta APP** (збірка для Debian, лише «Інструменти») на весь екран (`sekta --fullscreen`, systemd `--user` unit `sekta-kiosk.service`). Ставить **актуальну версію** з GitHub Releases (`sekta-app`, перевірка SHA-256, залежності — через `apt`); повторний запуск пункту оновлює застосунок. **amd64 або arm64** (Raspberry Pi 4/5 тощо; пакет під архітектуру машини обирається сам, arm64 — з Sekta APP 1.7.2), Debian 12+ з графічним робочим столом. Вхід у застосунок — контрольною фразою «Інструментів». Замінює Chromium-kiosk (пункт 7), якщо він уже стоїть.

## Мінімальні вимоги заліза

Розраховано на host + Debian VM (модуль 5).

| Компонент | Мінімум | Рекомендовано |
|---|---|---|
| **CPU** | x86-64, 4 потоки, VT-x / AMD-V. Intel — **не нижче 8-го покоління** | Intel 10-е+ / 6+ потоків |
| **IOMMU** | VT-d / AMD-Vi у BIOS (для GPU passthrough) | — |
| **RAM** | 12 GB (host + Debian VM 8 GB); без VM — 4 GB | 16 GB+ |
| **Диск** | 64 GB SSD | 128 GB+ NVMe |
| **NIC** | 1 | — |
| **USB** | флешка під бекапи (модуль 4) | — |
| **GPU** | лише якщо треба passthrough (модуль 2) | iGPU/dGPU з підтримкою VFIO |

Орієнтовний розподіл RAM/диску: host ~2 GB / 16 GB, Debian VM 8 GB / 10 GB.

Примітки:
- **Intel: не нижче 8-го покоління (Coffee Lake, UHD 630).** Старіші iGPU нестабільні у VFIO-passthrough; 8-е покоління або новіше дає надійний проброс і сучасні драйвери.
- Для **GPU passthrough** обовʼязково увімкнути VT-d/IOMMU у BIOS/UEFI, інакше модулі 2/3 не спрацюють.
- Без Debian VM (модуль 5) вимоги падають до самого хоста.
